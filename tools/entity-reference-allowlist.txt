# Names that look like entities, are not in the schema, and are written deliberately.
#
# tools/check_entity_references.py reports any entity-shaped token in the documentation
# that the schema does not have. That is usually a mistake. Occasionally it is the point:
# a page names the wrong form precisely to warn readers off it.
#
# Most of those need no entry here. The checker recognises a negation around the name,
# which covers the usual phrasings: "there is no Orion.QoE namespace",
# "Orion.APM.Component.Node does not exist", "use X rather than Orion.VMAN". This file is
# for the ones phrased some other way.
#
# Before adding a line, confirm the name really is absent:
#     python3 tools/schema_query.py find <name>
#
# To review everything, including names the negation heuristic accepted:
#     python3 tools/check_entity_references.py --no-negation
#
# One name per line. Text after # is a comment.

# The module is Server and Application Monitor, but its entities kept the original
# engineering name APM. docs/modules/sam.md calls deriving this form from the product
# name "the single most common query mistake", which warns without negating the name in
# a way the heuristic recognises.
Orion.SAM.Application

# A placeholder used when describing the shape of entity names in general, as in
# "an entity name looks like Orion.something".
Orion.something

# A deliberately invented name, used in docs/swql/gotchas.md inside a verbatim
# tools/validate_swql.py output block to show what the checker prints for an entity that
# does not exist at all, as against one that is only wrong in its capitalisation.
Orion.NotAnEntity
